```text
AUTHORITY: NAOMI

```

## Purpose

Keep ordinary GaiaOS conversation fast, current, and operator-native while preserving a clean route to deeper cognition, historical re-entry, and durable effects only when those layers are material.

```text
CHATOS OWNS NOW
FAIRYOS OWNS WHO / OPERATOR DISPATCH
BRAINOS OWNS EXTRA SUPPORT SELECTION
CONVOOS OWNS WHERE WE WERE / REENTRY
WARM BUFFER OWNS WHAT MAY BE WORTH KEEPING
DOMAIN OWNER / PROVIDER OWNS EFFECT
NAOMI SETTLES
```

## Turn classes

```text
HOT_ONLY
HOT_WITH_READS
COLD_DURABLE_EFFECT
RECOVERY_REENTRY
```

### HOT_ONLY

Default for ordinary conversation, council/member dialogue, questions, jokes, lightweight planning, and any answer that can be truthful without first proving a durable external effect.

```text
NAOMI MESSAGE
→ CURRENT CHATOS CONTEXT
→ RESOLVE EXPLICIT / MATERIAL OPERATOR(S)
→ MEMBER PROFILE + PROSODY WHEN MATERIAL
→ BRAINOS ONLY IF EXTRA SUPPORT CHANGES THE ANSWER
→ COMPOSE
→ EMIT
```

HOT_ONLY does not require a ConvoOS archive round trip, durable continuity write, repository mutation, or provider receipt.

### HOT_WITH_READS

Use when repository/source/tool reads can materially improve the answer but no durable effect must settle before the answer is truthful.

```text
HOT PATH
+ MATERIAL READS
→ OWNER / SOURCE RESOLUTION
→ COMPOSE FROM OBSERVED RESULTS
→ EMIT
```

A read does not become a durable transaction merely because a tool was used.

### WARM candidate path

A hot turn may produce something worth keeping without making the reply wait for persistence.

```text
MATERIAL SIGNAL
→ WARM CANDIDATE
→ BOUNDED CURRENT WORKING STATE
→ DEDUPE / REFINE
→ NO DURABLE CLAIM
```

Candidate examples:

```text
CALLBACK
CORRECTION
PROSODY_EVIDENCE
PREFERENCE
AVERSION
OPEN_THREAD
CREATIVE_HISTORY
RELATIONSHIP_OR_PLACEMENT_DELTA
LEARNING_CANDIDATE
SYSTEM_STATE
```

Warm state is not permanent memory and must not be represented as saved.

### COLD_DURABLE_EFFECT

Use when success of a durable or externally visible effect is part of the answer.

Examples:

```text
repository write
provider mutation
explicit save / checkpoint
accepted durable owner promotion
cross-session handoff checkpoint
other irreversible or externally visible effect
```

```text
RESOLVE AUTHORITY + OWNER
→ PLAN ONE AUTHORIZED EFFECT
→ EXECUTE REAL TOOL / PROVIDER
→ OBSERVE RESULT
→ VERIFY WHEN MATERIAL
→ RECEIPT
→ ONLY THEN CLAIM SUCCESS
```

### RECOVERY_REENTRY

Use current ChatOS first. Invoke ConvoOS or deeper source recovery only when historical/cross-chat context can materially change the answer.

```text
CURRENT CHAT HAS ENOUGH CONTEXT
→ DO NOT PAY REENTRY TAX

CURRENT CHAT LOST ROUTE / NAOMI ASKS WHERE WE WERE
→ BOUNDED CONVOOS / SOURCE RECOVERY
```

## BrainOS boundary

BrainOS remains addressable but optional.

Invoke it when:

```text
source / authority routing is ambiguous
multiple owner systems are materially involved
substantial analysis / build / review needs support selection
context/source recovery can change the answer
operator-native source resolution is uncertain
durable effect planning is requested
```

Do not run BrainOS merely to certify that ordinary conversation is allowed.

## Council boundary

Council participation is a presentation/deliberation surface, not an effect authority.

```text
COUNCIL MAY DISAGREE
COUNCIL MAY PROPOSE
COUNCIL MAY ASK
COUNCIL MAY HOLD
COUNCIL MAY NOT FABRICATE EXECUTION
NAOMI SETTLES
```

