# GaiaOS Stage 9L · One-click safe checks

**Owner:** NAOMI / LIGEIA. **Engineering:** 58 · ANVIL. **Mode:** HEATDEATH. **Production deployment:** owner-controlled.

## Scope

The first live Stage 9I owner-relayed signed receipts report successful A+B retrieval on a COLLISION case. Stage 9J adds a bounded SELECT-only classification of genuine historical-memory prerequisites; Stage 9K offers that single diagnostic on a small mobile page. The user requested one-click operation across the remaining safe checks instead of individually navigating several pages and copying several JSON receipts.

Stage 9L adds an owner-only standalone control panel at `GET /gaiaos/memory/one-click-console`. After entering the existing private GaiaOS bearer key locally, the owner clicks **Run all safe checks** exactly once. The browser makes **one** authorized POST to `/gaiaos/memory/one-click-readiness`. The server sequentially invokes *already-existing, bounded read-only code*, and returns one typed and allowlisted redacted report with a plain-English result. No second semantic model call and no personal memory content is transferred to the browser by the server.

## Included in one click

1. Identify the **actual running carrier's source commit** using the local health contract and Render's deploy-commit environment proof. This is a same-process claim, not independent external HTTP reachability or evidence that a new source update was deployed.
2. Verify the **effective HEATDEATH mode and BIGBANG release lock**. Fail closed and skip every MemoryOS diagnostic if the lock cannot be validated.
3. Verify the configured **remote Turso-backed MemoryOS** access contract. If absent, fail closed before source scans.
4. Run the existing **real owner-approved technical preflight**. Report the number of approved current records, partial-five-case eligibility, and whether a full six-case historical sample is only *prepared but untested*. Never disclose statements, source IDs or staged questions.
5. Run the existing **Stage 9J bounded historical audit**. Redact to a finite reason code and six bounded aggregate counts only when the scan is complete. A real historical candidate is not evidence that a historical retrieval test passed.
6. If two approved current records exist, run the existing **two-source literal wiring smoke** and its before/after native HEATDEATH parity check. Even PASS_LITERAL_WIRING_ONLY proves only literal retrieval, not owner semantic judgment, historical quality or generalized paraphrase accuracy.

HEATDEATH is verified once before all reads **and again afterward** with the same mode and control version. If it changes, the overall result fails closed. Every sub-check has its own finite HOLD/skip status, so one missing historical prerequisite does not erase evidence that the current literal path worked.

## Everything that deliberately remains separate

This is one-click for **safe checks**, not a one-click override of human authority. The owner must still judge semantic relevance; exact private source quotations for COLLISION remain owner-selected; paid OpenAI/AUGURY inference requires separate fresh explicit consent because the earlier one-call authorization is consumed. No new records or owner supersessions may be fabricated to satisfy the historical gate. Commits, PR merges, Render redeploys, emergency control mutations and BIGBANG activation are not executed by this read-only button.

No periodic task, canary, extra GitHub notification workflow or shared secret storage is introduced. The existing manual Render deployment process and isolated HEATDEATH recovery image are unchanged. All six individual E-LANES and `//PW:PRESERVE//` remain protected.

## Privacy and test contract

The static GET page uses a fresh CSP nonce, no-store/no-referrer and same-origin requests. It never obtains an API key from GitHub or the URL; the key is entered into a password input on the local page and is used only in the explicit owner's POST. It is never included in the copied report.

The response includes only finite reason/status enums, booleans, bounded counts and an authenticated-process running commit (40 lowercase hex when actually provided), with a constant full-release HOLD. Underlying private statements, record IDs, queries, quote excerpts, internal errors, arbitrary provider text and unknown reason codes are dropped by allowlisting on the server and again by the browser. Fail-closed errors are not mistaken for zero historical evidence. An incomplete audit never copies apparently authoritative aggregate counts.

The existing Stage 7 PR gate runs the isolated six-check regression suite, read-only/invalid-key denial, fake-success and unrecognized-secret rejection, private-safe copy, simulated **actual served JavaScript** button click, original Stage 9F–9K regressions, and both the normal carrier and independent HEATDEATH image builds. The permanent console registry recognizes the new page, so future JavaScript syntax errors and unbound buttons fail CI before merge.
