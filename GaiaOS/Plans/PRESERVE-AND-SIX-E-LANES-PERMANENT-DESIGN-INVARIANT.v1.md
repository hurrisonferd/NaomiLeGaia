## Owner's explicit no-deprecation rule

Naomi: "No matter what galaxy becomes we definitely will never get rid of the preserve command or E-LANES, both are super imperative to keep."

These are foundational and permanent design requirements, not optional compatibility features, UI conveniences, expendable legacy mechanics or experimental GALAXY plugins:

1. **`//PW:PRESERVE//` remains supported and accessible** with its existing explicit-owner authority, provenance, pending/approved/evidence distinctions, readback and receipt requirements. No memory enhancement, aggressive salience scoring, automatic summarization or host replacement may silently bypass or disable it. The GitHub/source checkpoint pathway and, when independently available/authorized, live carrier memory write pathways must be distinguished; do not claim a Turso commit from a GitHub document.
2. **Exactly six separate owner-defined Prime Daemon E-LANES remain individually readable, writable by their established authorized processes, versioned, exportable and restorable.** Names at this checkpoint: VERA, ANVIL, SELENE, ORIN, KESTREL and NIMUE. Do not flatten them into a composite universal voice, merge ownership/provenance, make GALAXY's cross-link graph their new identity authority, or sacrifice member-specific context in any migration. VASKON remains temporary explicit synthesis, not a seventh permanent E-LANE.
3. **BIGBANG adds capability; HEATDEATH restores the existing legacy operating model.** Exactly two user-facing memory operating modes. GALAXY may enhance read salience, semantic links, gravity, historical awareness and organization, but both modes must preserve the same authoritative current records, owner approvals, `//PW:PRESERVE//`, `CANDIPULL`, `MEMSAV`, six E-LANES, append-only evidence and readback. HEATDEATH must not mean silently restoring obsolete records or degrading preservation authority.
4. **Gate integration on the invariants at every stage.** Unit and actual-route tests must exercise preservation entry points and six distinct E-LANES in both modes as they are built; source/image CI is not live proof. Include missing-record HOLDs, broken-GALAXY startup, independent legacy recovery, schema compatibility, current-record reuse, cross-carrier portability, export/restore and observed restart proof before declaring a live safety claim.
5. **No silent removal by refactoring, migration or performance cleanup.** A new storage engine, renamed source path or future owner-controlled SovereignOS repository must provide verified equivalent preservation commands and individually restored E-LANES before a separately owner-authorized cutover. Migrations must preserve original source/history; bound actual gaps, never invent missing personal or member memories. Additive interoperability is permitted; destructive substitution is not authorized by general GALAXY approval.
6. **Preservation is a recovery contract, not merely an archival request.** A saved checkpoint must identify where it was actually written, which six lanes were actually updated, which build/deploy tests were observed and which remain pending. New GPT conversations must re-read canonical GitHub source or other verifiable loaded context, not pretend a repository write automatically changed ChatGPT's internal memory.

This directive is inherited by planning, the loader, merge reviews, production readiness, Phylactery offline backup, and future SovereignOS migration. A failure of either foundational safeguard blocks any BIGBANG release even if retrieval quality improves.
