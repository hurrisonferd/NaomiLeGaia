## One-click read-only lineage reconnaissance

Stage 9M adds `api/gaiaos_revision_lineage_scout.py` and includes its result inside the *existing* Stage 9L **historical evidence** subcheck when the full bounded audit identifies zero verified owner SUPERSEDES. No additional button, repeated canary, scheduler, cron, model call or separate JSON receipt is required.

The scout performs **SELECT only** over the same 100 most recent technical-keyword MemoryOS records as Stage 7 and at most 100 already VERIFIED owner REVISES edges. It requires configured remote Turso, effective HEATDEATH, BIGBANG disabled, and unchanged mode/control version across the scan. Results count verified owner REVISES edges that connect two *already existing*, real owner-authorized technical records with eligible source provenance, an ACTIVE newer record and a distinctive **genuine existing** old-version marker absent from eligible current technical statements. Synthetic, fixture, test, calibration and canary sources are excluded identically to Stage 7.

The result is a **finite, redacted advisory** under the existing historical evidence card: number of owner REVISES, eligible real technical pairs, ACTIVE newer records and distinctive old-marker leads. It never includes statements, IDs, sources, version marker strings or owner keys. An incomplete 101-row scan means HOLD, **not zero candidate records**. A failure in this advisory does not discard the independent Stage 9L evidence that current retrieval, HEATDEATH, or remote storage passed.

`LEADS_FOUND_OWNER_REVIEW_ONLY` is **not** a SUPERSEDES relation. REVISES by definition leaves the older record ordinary-current eligible. The scout does not create a verified owner SUPERSEDES edge, mutate any MemoryOS record, alter governance, backdate source events or infer that two records are actually successive versions. No candidate is promoted automatically. If no real owner revision leads exist, the outcome simply documents that absence in the current bounded window and stops. A genuine later owner decision and separate write authorization are required if the user ever wishes to establish a historically true supersession.
