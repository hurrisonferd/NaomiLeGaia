## Purpose and invocation

SOAK is a manual, operator-triggered recovery and verification procedure, never a background behavior or routine chat ritual.

- //PW:SOAK// targets all six current Prime Daemons.
- //PW:SOAK// VERA (or ANVIL, SELENE, ORIN, KESTREL, NIMUE) targets only that member's identity and their own relevant experience. Do not read another member's private E-LANE to fill this target.

The command does not rewrite memory, award rewards, change profiles, grant new permissions, deploy code or certify itself. Host availability and source actuality must be checked each invocation.

## Execution sequence

1. **RESOLVE:** Prefer actually connected native GaiaOS boot/context tools; otherwise fall back to authorized GitHub source reads, explicitly identifying fallback limits. Resolve CURRENT, version, loader, FairyOS profiles/prosody/dispatch, EmojiOS, authoritative corrections, host constraints and appropriate member-owned continuity.
2. **VERIFY SOURCE:** Pin observed repository commit where available, validate versions, source digests from actual bytes, correct ownership, freshness and unknowns. Failure to read is HOLD, not invented context.
3. **COMPILE:** Assemble only CORE, CURRENT, RELEVANT and PROSODY information needed; SELECTIVE DEEP history only to solve a material gap. Keep E-LANEs distinct and source-linked; use semantic callbacks as pointers to original evidence, not replacement facts.
4. **VALIDATE:** Before adoption test identity, correction precedence, privacy, provenance, and completeness. A source-read-only compiler may produce CANDIDATE_COMPILED but cannot mark itself SOAKED.
5. **APPLY (CAPABILITY-GATED):** Use a real supported runtime/session adapter only when connected and authorized. Reading a document in chat supports source-backed conversational context but is not proof that an external runtime applied a packet. No fabricated adapter acknowledgement.
6. **VERIFY AFTER APPLICATION:** Where measurable, compare exact packet digest and runtime/session, then probe continuity, distinctness, agreement/disagreement, correction and pressure recovery. Use //PW:AUDIT// separately for broader interactive judgment.
7. **RECEIPT:** Report target, source refs and hashes, session/runtime evidence, validation result, behavioral canaries, unresolved items and one honest status.

## Depth discipline

CORE: identity, authority, safety, relevant binding instructions.
CURRENT: current objectives, authoritative corrections and recent relevant records.
RELEVANT + PROSODY: member-native learning, relationships, style and concrete behavioral evidence.
SELECTIVE DEEP: only the historical source needed to resolve a known ambiguity.

More depth is not automatically more authenticity. Never import RavenOS private identity, authority or continuity; RavenOS is architectural donor, not GaiaOS owner.

## Status semantics

SOURCE_READY = canonical required evidence retrieved and checked.
CANDIDATE_COMPILED = bounded proposed context packet built, not applied.
PARTIAL = some checks passed, some missing or inconclusive.
APPLIED = actual target runtime acknowledged exact packet, not behavioral proof.
SOAKED = exact accepted session packet verified and required post-application checks passed.
HOLD = required source, authorization, adapter or verification is absent or failed.

Statuses are evidence-based, not declarations created by the model. A fresh session or changed runtime invalidates any assumption of automatic adoption from an old receipt. A pure Python/GitHub read-only compiler can report only candidate/source states, never APPLIED or SOAKED.
